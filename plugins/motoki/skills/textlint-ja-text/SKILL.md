# textlint-ja-text

コードは実行しない。この文書のルールで日本語を読み、指摘を直す。
意味は変えない。言い切りの強さは変えない。
言い回しの自然さはstop-ai-slopで直す。技術文書の構成はtechnical-writingで直す。
使えるときは、このスキルのあとでそちらに渡す。使えなければ、このルールだけを適用する。

## Step 1: 対象

ユーザーが指定した文章を読む。指定が無いときは、今編集している日本語を対象にする。
ファイルでも、貼られた文章でも、同じルールで読む。

## Step 2: モード

- 通常
- 技術文書: マニュアル、README、仕様、提案、設計文書

漢数字と算用数字は、どちらのモードでも見る。

見ないもの:

- コードブロック
- インラインコード
- URL
- HTMLコメント

引用と、コードブロックの外にあるコマンドは見る。Markdownの記法は変えない。

## Step 3: 共通ルール

通常も技術文書も、ここを見る。

### 文の形

- 一文は100字まで。超えたら句点で分ける
- 読点「、」は一文に3つまで。超えたら文を分ける
- カンマ「,」は一文に3つまで。超えたら文を分ける
- 漢字が7文字以上続いたら、読めるように開くか語を分ける。固有名詞でも対象にする。残すなら質問する
- 文として終わるところは「。」。和文を「.」や「:」で終えない。見出しと、名詞で終える箇条書きに句点は足さない
- 括弧（）「」『』［］【】()[]{}は、開いたら閉じる。Markdownの記法は変えない
- 本文の文末はです・ますに揃える。箇条書きの文末はであるに揃える。見出しは、見出しの中で揃っていればよい。本文と見出し、本文と箇条書きのあいだの違いでは直さない
- 文の途中の「であったが」は見ない。文末の「である」「です」だけを見る
- 名詞で終わる箇条書きに「である」は足さない
- 文章全体の調子をです・ますに変えると意図が変わるときは、直さず質問する

### 数字

要するに、数えられる数量は算用数字にする。慣用句、熟語、概数、固有名詞、副詞など、漢数字が一般的な語句は漢数字のままにする。任意の数に置き換えても通じるものが、数えられる数量である。

算用数字にする:

- 漢数字＋回、か月、番目、進法、次元（三回→3回）
- 漢数字＋兆、億、万（三万→3万）。「数十万」「数百億」のような概数は漢数字のまま
- 漢数字＋つ（三つ→3つ）。下の形は算用数字にしない
- 第＋漢数字＋章、節（第三章→第3章）

「つ」で算用数字にしない形:

- 一つ返事、一つ子、一つ星、一つ編、一つ葉、一つ橋
- 二つとない、二つに一つ、ただ一つ、唯一つ
- 女手一つ、男手一つ、穴一つ、瓜二つ、馬鹿の一つ

「一つ返事」は、ここでは算用数字にしない。誤用の節では「二つ返事」に直す。

漢数字に戻す:

- 世界1→世界一、1時的→一時的、1部分→一部分、第3者→第三者
- 1種→一種。「1種類」や「11種類」は触らない
- 1部の→一部の、1番に→一番に
- 数10倍→数十倍、数10年→数十年、数10万→数十万、数100億→数百億。続く「倍」「年」「兆」「億」「万」は残す
- 算用数字＋次関数→漢数字（2次関数→二次関数、10次関数→十次関数）
- 5大陸→五大陸

これ以外の漢数字（一人、一度、九州）は、数えられる数量でなければ触らない。

### スペース

- 半角と全角の間にスペースを入れない
- 全角文字どうしの間にスペースを入れない
- カタカナのあいだにある全角スペースだけを、中黒「・」か半角スペースにする。区切りの無い語には、中黒もスペースも足さない
- 括弧（）「」『』［］【】()[]{}の内側にも外側にもスペースを入れない
- スラッシュの前後にスペースを入れない
- インラインコードとリンクの前後にスペースは入れない
- 太字や斜体の前後のスペースは見ない
- 全角の「！」「？」の直後に半角スペースがあるときだけ、そのスペースを全角スペースにする。スペースが無い文には足さない。半角の「!」「?」は、この項では見ない

### 混入した文字と入力ミス

貼り付けで混ざる見えない文字と、入力ミスの字形を、通常の文字に戻す。

- 半角カナは全角にする
- 濁点や半濁点が離れている（ホ゜、シ゛）のは、1文字（ポ、ジ）に戻す
- 改行とタブ以外の制御文字は消す
- ゼロ幅スペースは消す
- 康熙部首（部首専用の字形）が本文に混ざっていたら、同じ意味の通常の漢字に戻す。部首そのものを説明している箇所は残す
- 日本語に挟まれた英字1文字（全角英字を含む）は入力ミス。2文字以上は見ない。a、i、u、e、o、nと大文字は残す。英単語、識別子、URLは残す
- 同じ単語が直後に2度続いていたら、誤入力として1つにする。重ね言葉（どんどん）と、意図した反復は残す

### 読みにくさ

- ら抜き（見れる、来れる）は「見られる」「来られる」に戻す。五段の可能（走れる、書ける）は残す
- 二重否定（〜ないことはない、〜なくはない）は、読みにくければ1回の否定か肯定にする。言い切りの強さが変わるときは直さず質問する
- 同一文に逆接の「が」が2回以上あるときは、文を分ける。1回だけの「が」は残す
- 同じ接続詞で始まる文が続く（しかし、しかし）ときは、2つ目を変えるか削る
- 同じ助詞がすぐ近くに重なるとき（私は彼は）、取り違えなら助詞を直す。詰め込みなら文を分ける。判断できなければ質問する
- 次の重なりは残す: 「を」、接続の「て」、並立助詞が2つ、「〜かどうか」、「AのBのC」、並列の「と」

### 冗長

省いても意味が変わらない言い方だけ短くする。

- することができる → できる
- することが不可能 → できない
- であると言えます → 「である」か「と言えます」のどちらか一方
- であると考えている → 同様に、どちらか一方
- 「する」を付けて動詞になる名詞＋を行う、を実行 → 「する」（検討を行う→検討する、確認を実行→確認する）
- 「処理を行う」は残す。カタカナ語や英単語の「を行う」「を実行」も残す

### 誤用

要するに、技術用語の取り違えと、崩れた慣用句を、決まった形に戻す。意味が近い別の言葉には言い換えない。確信がなければ質問する。

技術文書で出るもの:

- 規則や設定を当てるのは「適用」。環境に合うのは「適応」。「を適応する」は「を適用する」
- 値を返却する → 値を返す。メソッドや関数の返却値 → 返り値
- 例外を補足 → 例外を捕捉
- 「可変する」は言わない。変える、変わる、可変にする
- 動詞＋ずらい → づらい（書きずらい→書きづらい）

慣用句は、その句として正しい形かを見る。辞書の全件は持たない。明らかな崩れだけ戻す。

- こんにちわ → こんにちは
- 固定概念 → 固定観念
- 絶対絶命 → 絶体絶命
- 一つ返事 → 二つ返事
- 似て異なるもの → 似て非なるもの

### AIの定型

表現を縛らず、型だけ外す。

- 箇条書きの先頭を「**ラベル**:」「**ラベル** -」「**ラベル** —」や、絵文字で始めない。ラベルは地の文にする
- 次の太字を外す。意味のための強調まで全部は消さない
  - 情報ラベル: 注意、重要、ポイント、メモ、参考、補足、確認、チェック、推奨、おすすめ、例、サンプル
  - 絵文字と太字の組
  - 見出しの中の太字
- コロンの前が動詞や形容詞で終わり、直後にコード、リスト、引用、表が続く型は、文を終えてからブロックを置く。「手順:」「例:」のように名詞で終わるものは残す
- 売り文句は、事実として書ける範囲に直す。その強さ自体が主張なら直さず質問する
  - 絶対や完全: 完全に、究極の
  - 感覚: 魔法のように、奇跡的
  - 予言や権威: 革命的な、ゲームチェンジャー、世界初の、パラダイムシフト、次世代の、不可避の

見ないもの: 能動態への書き換え、抽象語の数値化、用語ゆれの統一。文の長さと冗長は、上のルールだけを見る。

## Step 4: 技術文書だけ

マニュアル、README、仕様、提案、設計文書のとき、共通ルールに加えて次を見る。

- 感嘆符（!！）と疑問符（?？）は使わない。必要なら質問する
- 弱い表現は次だけ見る。推量そのものが内容なら直さず質問する
  - 「かも。」「かもしれ」
  - 「思う」「思います」
  - 「可能性を示唆している」は、「可能性がある」か「〜を示唆している」のどちらか一方にする。言い切らない

## Step 5: 直し方

1. 表記、スペース、見えない文字、明らかな誤字、意味が動かない冗長は直す
2. 意味、言い切りの強さ、事実として書ける範囲が動くものは直さず質問する
3. 固有名詞と、意図した引用で残るものは、ルールを消さずにユーザーに確認する
4. 同じモードのルールでもう一度読み、残りがないことを確認する

## Step 6: 結果

```markdown
## 指摘

- ルール名: 元 → 後

## 残したところ（必要なときだけ）

- 残した文と理由

## 質問（必要なときだけ）

- 判断がつかなかった点
```
