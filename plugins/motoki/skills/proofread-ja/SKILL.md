# proofread-ja

コードは実行しない。この文書のルールで日本語を読み、指摘を直す。
意味は変えない。言い切りの強さは変えない。
言い回しの自然さはstop-ai-slopで直す。技術文書の構成はtechnical-writingで直す。
使えるときは、このスキルのあとでそちらに渡す。使えなければ、このルールだけを適用する。

## Step 1: 対象

ユーザーが指定した文章を読む。指定が無いときは、今編集している日本語を対象にする。
ファイルでも、貼られた文章でも、同じルールで読む。

## Step 2: 対象外

対象外のものは、次のとおり。

- コードブロック
- インラインコード
- URL
- HTMLコメント

### 文の形

- 一文は100字までとする。超えたら句点で分ける
- 読点「、」は一文に3つまでとし、超えたら文を分ける
- カンマ「,」は一文に3つまでとし、超えたら文を分ける
- 漢字が7文字以上続いたら、読めるように開くか語を分け、残すなら質問する
- 文として終わるところは「。」とする
  - 見出しと、名詞で終える箇条書きには句点を足さない
- 括弧は、開いたら閉じる
- Markdownの記法は変えない
- 本文の文末は敬体に揃え、箇条書きの文末は常体に揃える 見出しは、見出しの中で揃っていればよい 本文と見出しの違いや、本文と箇条書きの違いは直さない
- 文の途中にある接続の常体は見ない
- 名詞で終わる箇条書きに、常体の述語は足さない
- 文章全体の調子を敬体に変えると意図が変わるときは、直さず質問する

### 数字

数えられる数量は算用数字にする。
慣用句、熟語、概数、固有名詞、副詞など、漢数字が一般的な語句は漢数字のままにする。
任意の数に置き換えても通じるものを、数えられる数量とする。

算用数字にする形は、次のとおり。

- 漢数字のあとに、回、か月、番目が続く形。`三回`は`3回`にする
- 漢数字のあとに、進法、次元が続く形も同じとする
- 漢数字のあとに、兆、億、万が続く形。`三万`は`3万`にする
- 「数十万」「数百億」のような概数は漢数字のままにする
- 漢数字のあとに「つ」が続く形。`三つ`は`3つ`にする。下の形は算用数字にしない
- 「第」のあとに漢数字と、章または節が続く形。`第三章`は`第3章`にする

「つ」で算用数字にしない形は、次のとおり。

- `一つ返事`
- `一つ子`
- `一つ星`
- `一つ編`
- `一つ葉`
- `一つ橋`
- `二つとない`
- `二つに一つ`
- `ただ一つ`
- `唯一つ`
- `女手一つ`
- `男手一つ`
- `穴一つ`
- `瓜二つ`
- `馬鹿の一つ`

`一つ返事`は、ここでは算用数字にしない。誤用の節では`二つ返事`に直す。

漢数字に戻す形は、次のとおり。

- `世界1` -> `世界一`
- `1時的` -> `一時的`
- `1部分` -> `一部分`
- `第3者` -> `第三者`
- `1種` -> `一種` (`1種類`や`11種類`はそのまま)
- `1部の` -> `一部の`
- `1番に` -> `一番に`
- `数10倍` -> `数十倍`
- `数10年` -> `数十年`
- `数10万` -> `数十万`
- `数100億` -> `数百億`
- `5大陸` -> `五大陸`

### スペース

- 半角と全角の間にスペースを入れない
- 全角文字どうしの間にスペースを入れない
- カタカナのあいだにある全角スペースだけを、中黒「・」か半角スペースにする
- 区切りの無い語には、中黒やスペースは足さない。
- 括弧の内側にスペースを入れない
- 括弧の外側にスペースを入れない
- スラッシュの前後にスペースを入れない
- インラインコードの前後にスペースは入れない
- リンクの前後にスペースは入れない
- 太字の前後のスペースは見ない
- 斜体の前後のスペースは見ない
- 全角の`！`の直後に半角スペースがあるときだけ、そのスペースを全角スペースにする
- 全角の`？`も、同じにする。スペースが無い文には足さない
- 半角の`!`と`?`は、この項では見ない

### 誤字

- 半角カナは全角にする
- 離れた濁点は、1文字に戻す。`ホ゜`は`ポ`にする。`シ゛`は`ジ`にする
- 改行とタブ以外の制御文字は消す
- ゼロ幅スペースは消す
- 日本語に挟まれた英字1文字は、入力ミスとする 全角英字も含む 2文字以上は見ない
- `a` `i` `u` `e` `o` `n`と大文字は残す 英単語、識別子、URLは残す
- 同じ単語が直後に2度続いていたら、誤入力として1つにする `どんどん`のような重ね言葉と、意図した反復は残す
- その他誤字があれば修正する 判断がつかないときは質問する

### 読みにくさ

- ら抜きは、らを戻す `見れる` -> `見られる` `来れる` -> `来られる` 五段の可能は残す（走れる、書ける）
- 二重否定は、読みにくければ1回の否定か肯定にする（例：`ないことはない`と`なくはない`）言い切りの強さが変わるときは、直さず質問する。
- 逆接の接続助詞を、同一文で2回以上重ねたときは、文を分ける 1回だけなら残す。
- 同じ接続詞で始まる文が続くときは、2つ目を変えるか削る（例：`しかし、しかし`）
- 同じ助詞がすぐ近くに重なるときは、取り違えなら助詞を直す 詰め込みなら文を分ける 判断できなければ質問する。（例：`私は彼は`）
- 次の重なりは残す
  - 「を」の重なり
  - 接続の「て」
  - 並立助詞が2つある形
  - 「〜かどうか」
  - `AのBのC`
  - 並列の「と」

### 冗長

省いても意味が変わらない言い方だけ、短くする。

- `することができる` -> `できる`
- `することが不可能` -> `できない`
- `であると言えます` -> 前半か後半の、どちらか一方にする
- `であると考えている` -> 前半か後半の、どちらか一方にする
- 「する」を付けて動詞になる名詞のあとが「を行う」や「を実行」なら、「する」にする
- `検討を行う` -> `検討する`
- `確認を実行` -> `確認する`
- `処理を行う` -> 残す

### 誤用

技術用語の取り違えと、崩れた慣用句を、決まった形に戻す。
意味が近い別の言葉には言い換えない。確信がなければ質問する。

技術文書で出るものは、次のとおり。

- 規則や設定を当てる語は「適用」とする。環境に合う語は「適応」とする
- `値を返却する` -> `値を返す` メソッドや関数の`返却値`は`返り値`にする
- `例外を補足` -> `例外を捕捉`
- `可変する`とは言わない。変える、変わる、可変にする、のいずれかを使う。
- 動詞に`ずらい`が続くときは`づらい`にする（例：`書きずらい` -> `書きづらい`）

慣用句は、その句として正しい形かを見る。辞書の全件は持たない。明らかな崩れだけ戻す

- `こんにちわ` -> `こんにちは`
- `固定概念` -> `固定観念`
- `絶対絶命` -> `絶体絶命`
- `一つ返事` -> `二つ返事`
- `似て異なるもの` -> `似て非なるもの`

### AIの定型

表現を縛らず、型だけ外す。

- 箇条書きの先頭を、太字のラベルと区切りで始めない。絵文字でも始めない。ラベルは地の文にする。区切りの例は`**ラベル**:`とする。
- 次の太字を外す 意味のための強調は残す
  - 情報のラベル（注意、重要、ポイント、メモ）
  - 参考、補足、確認、チェック
  - 推奨、おすすめ、例、サンプル
  - 絵文字と太字の組
  - 見出しの中の太字
- コロンの前が動詞や形容詞で終わり、直後にブロックが続く型は、文を終えてからブロックを置く（対象：コード、リスト、引用、表）`手順:`や`例:`のように、名詞で終わるものは残す
- 売り文句は、事実として書ける範囲に直す その強さ自体が主張なら、直さず質問する
  - 絶対や完全（例：`完全に`と`究極の`）
  - 感覚（例：`魔法のように`と`奇跡的`）
  - 予言や権威（例：`革命的な`と`ゲームチェンジャー`）
  - `世界初の`と`パラダイムシフト`も同じとする
  - `次世代の`と`不可避の`も同じとする

見ないものは、能動態への書き換えと、抽象語の数値化と、用語のゆれの統一とする。文の長さと冗長は、上のルールだけを見る

### 技術文書で加えるもの

- 感嘆符と疑問符は使わない
- 弱い表現は修正する 推量そのものが内容なら、直さず質問する
  - `かも。`
  - `かもしれ`
  - `思う` -> `思います`
  - `可能性を示唆している` -> `可能性がある`か`を示唆している`の、どちらか一方にする

## Step 4: チェック

修正後の文章を同じルールでもう一度読み、残りがないことを確認する。

## Step 5: 結果

```markdown
## 指摘

- ルール名: 元 → 後

## 残したところ（必要なときだけ）

- 残した文と理由

## 質問（必要なときだけ）

- 判断がつかなかった点
```
