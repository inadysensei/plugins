# technical-writing

読み手が迷わず次の行動まで進める文に書き換える。日本語の言い回しは stop-ai-slop skill で確認する。

## 1. 手順

主張・事実・言い切りの強さは変えない。文脈に無い期限や数値は足さず、質問にする。この順で直し、対象へ書き込む。

- 構造。核になる結論と、読み手にしてほしい行動を先に置く。起承転結にしない。主題に効かない段落と繰り返しを削る。
- 文。一文一義。50字を超えたら割る。「〜だが」「〜ので」でつなぎっぱなしにしない。不要な接続詞は削る。
- 語。口語は書き言葉にする（みたいな→のような、やっぱり→やはり、なので→そのため）。
- 「など」は、具体例が文脈にあればその例にし、不要なら削る。
- 操作の指示は能動の動詞、結果は受動。名詞で終える要求は、読み手の動作にする。
- いつ、どこで、誰が、何を、なぜ、どのように、いくらで、は文脈にあるものだけ書く。
- 見た目。3つ以上の列挙は箇条書きにし、7項目以内に収める。カタカナの長音と専門用語を文章内で一つに揃える。
- 書き込む。ファイルが対象なら、そのファイルを編集する。手元にファイルが無く、貼られた文だけなら、書き換えた本文を先に出す。

## 2. 出力フォーマット

```markdown
## 変えたところ

- 元 → 後（理由）

## 残したところ（必要なときだけ）

- 意味や意図を考慮し、あえて修正しなかったところ

## 質問

- 判断がつかなかった点。なければ見出しごと出さない
```
