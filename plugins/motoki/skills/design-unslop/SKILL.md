# design-unslop

AIで作ったUIは、同じところで失敗します。表面はどれも光り、ラベルには絵文字があり、余白はその日のモデル任せで、文言は感嘆符で騒がしくなっています。design-unslopは作りを直し、製品は残します。機能、内容、節の順番はそのままです。変わるのは、大きさ、色、言葉、画像を意図して決めることです。

AIっぽさを取るだけでは半分です。きれいでも、どの製品でも成り立つ画面は次のテンプレートです。終わった画面は、この製品にしか成り立たないものにします。

AIっぽさと丁寧な作りの違いは、豊かさをどこに置くかです。AIっぽい画面は、背景、ボタン、境界、ラベルに色と効果をばらまきます。丁寧な作りでは、クロムを抑え、豊かさを1つか2つの見せ場に置きます。描いた物体、美しいチャート、製品の世界から来た画像です。

デザイナーが赤入れをするように、1層ずつ、画面全体を見ます。

文章そのものを直すときは、stop-ai-slopを使います。

## 良い画面

- **明るい要素は1つ。** 各画面に、色と作りを担う磨いたものを1つ置く。描いた物体、描いた風景、情報の多いチャートである。周りは静かにして、一目で分かるようにする。
- **静かなクロム。** ナビ、ボタン、文字は、少し色味のある無彩色とアクセント1色で作る。光らせない。明るい要素と競わせない。
- **考えが1文で言える。** ビジュアルが何を見せ、なぜこの製品のものかを1文で言える。
- **静かな場所に文字を置く。** 見出しは、画像かレイアウトの空けておいた場所に置く。短く具体的にする。主操作は1つ、従の操作は1つまでにする。その下に重ねない。
- **本物の製品と素材。** プレビューは本物のアプリに見え、データはありそうなものにする。物体には重さ、光、影がある。

どの見た目がうまくいき、どれが失敗するかは[references/visuals.md](references/visuals.md)にあります。学ぶための完成例は[references/refs.md](references/refs.md)にあります。画像を字形で描くようなコードの扱いは[references/effects.md](references/effects.md)にあります。

## 進め方

1. **画面を見る。** 描画しているファイルを探す。アプリを実行できるか、ファイルをブラウザで開けるなら、スクリーンショットを撮る。人が見るものを判断する。コードだけを見ない。
   - コードが無く、公開サイトのリンクだけなら、次のコマンドでページを保存する。その複製を直す。

     ```bash
     node <skill folder>/scripts/snapshot.mjs <url> design-unslop/original.html
     ```

     ローカルのHTMLファイルもURLの代わりになる。ユーザーが見ているテーマに合わせ、`--dark`か`--light`を付ける。スクリプトは`original.live.png`も保存する。保存した複製を描画し、2つを比べてから始める。先にページをスクロールするので、遅延読み込みの節と画像も取る。ページ側のスクリプトが描く動く背景は、保存先に残らない。監査では、公開ページで見たその背景を書く。
   - スクリーンショットだけなら、まず静的なHTMLファイル1つに、近くなるよう作り直す。それを原文として扱う。
   - どちらの場合も、結果はコードのページである。本物のサイトの所有者に渡せる。報告にその旨を書く。
2. **監査する。** [references/signs.md](references/signs.md)を順に見る。見つけた兆候を、場所つきで1行ずつ書く。
3. **どこまで変えるかを決める。** 計画の前に、監査を正直に読む。
   - **重い。** 色、文字、アイコン、文言の多くに兆候がある。下の手順をすべて行う。
   - **軽い。** ほぼデザインされていて、兆候が少し残っている。磨くモードにする。監査で見つけたものだけ直す。方向は既存のブランドから取る。新しい方向は作らない。パレット、書体、レイアウト、ビジュアルは残す。足りない見せ場や、ヒーローの風景は、変更にせず報告の提案にする。
   - **兆候がない。** そうと書く。細かい改善は多くて2つか3つにする。値を付ける。ユーザーが同意したときだけ適用する。そこで止める。良い画面を、違うものにするためだけに変えない。
4. **方向を書いて止める。** 下の5行を書く。監査と方向をユーザーに見せ、返事を待ってから編集する。方向を後で変えると、全部をやり直すことになる。質問するツールがあるなら、それを使う。無いなら、平文で聞いて止める。ユーザーが最初から進めてと言ったときだけ、待ちを省く。
5. **9つのパスを、この順で直す。** 1つのパスを画面全体で終えてから、次へ進む。ほぼすべての行が変わるなら、パスを順に計画し、すべてのパスを適用したうえで画面を一度に書く。余白が先である。リズムが合うと、他の見え方が変わる。文言は文字とレイアウトより先である。見出しの長さが、大きさと位置を決める。ビジュアルと動きは最後である。それらが無くても成立する画面に合わせる。
6. **確認する。** このファイル末尾のチェックリストを実行する。もう一度描画し、監査の一覧と比べる。残っているものは直す。
7. **報告する。** 方向、パスごとの変更を数行、書いた画像プロンプトを報告する。
8. **頼まれたとき、または共有したいときだけ記録する。** [ストーリー動画](#ストーリー動画)のとおりにストーリーファイルを作り、動画を描画する。最初から頼まれたなら、進めながら各パスをストーリーファイルへ書く。

1回の作業は短くします。確認のための描画は多くて3回です。画像を生成するなら、方向が決まってすぐ始めます。待ちません。その間に前のパスを進めます。

各パスの具体的な値は[references/tokens.md](references/tokens.md)にあります。

## 方向

手を付ける前に、短い5行を書きます。ページが言う、製品の働きと相手から導きます。流行からは導きません。

- **製品。** 何をする製品で、誰のためかを、平易な1文で書く。
- **性格。** 具体的な言葉を2つか3つ書く。`落ち着いている、正確、少し暖かい`や`速い、技術的、遊びがある`のようにする。`きれい`、`モダン`、`洗練`、`ミニマル`、`プレミアム`、`シンプル`は禁止する。どのテンプレートにも当てはまるため。
- **世界。** 製品が自然に属する場所か素材を書く。ノートアプリは紙とインクの近くに、監視ツールは計器と夜勤の近くに、旅行アプリは地図と窓の光の近くにある。この世界が、無彩色の色味、アクセント、ビジュアルを決める。
- **見せ場。** 画面が豊かな色、素材、細部を持つ場所を1つか2つ書く。製品が見せるものから選ぶ。プレビューの中の描いたカードや装置、系列ごとに色が意味を持つチャート、内容のそばに置いた世界の物体である。何であるかを書く。
- **印。** この製品だけが持つ小さい細部を1つ書き、一貫して使う。監視ツールの生きた状態の点、開発ツールのキーキャップ、学習アプリの手描きの下線、配送アプリの経路の線である。1つにする。5つにはしない。

ここでの例は、答えの形を示すだけです。目の前の製品から導きます。例がたまたま当てはまるときも同じです。

本物のブランドがあるなら、それを残します。ロゴファイル、色、AIっぽくない書体です。方向はそれに沿って作ります。紫から青へのグラデーション、きらめき、発光は、ロゴの中にあってもAIっぽさです。ユーザーがブランドだと言うとき以外、ブランドに数えません。

## 1. 余白

- すべてを4pxグリッドに乗せる。余白、パディング、間隔、固定の高さは4の倍数にする。28や104も、トークン一覧に無くてもよい。小さいコントロールの中の微調整は2pxでよい。何かを正確に中央へ置く奇数は残す。
- 同じものには同じ大きさを使う。リストの行は高さと間隔を1つにする。行の中のカードはパディングを1つにする。
- 余白でまとまりを示す。グループの中は、グループの間より狭くする。リストは1つの塊に、節は別のものに見える。
- 揃える。アイコンは1つの列に、ラベルは1本の線から、数字は1つの列で右に揃える。はぐれた`translate`や奇数のマージンで線からずらさない。
- 密度に合わせてパディングを決める。密なパネルとサイドバーはおよそ16、カードは20から24、ページの端は24から32にする。
- ナビはアプリで最も密な部分にする。行の高さは32から36、行間は2から4にする。アイコンは1つの列、ラベルは1本の線に乗せる。節のラベルは、上の節より自分の項目に近く置く。上は24、下は8のようにする。このパスのあとでサイドバーを測る。余白が最も崩れやすい場所である。
- リズムを壊す単発の値を消す。`mt-[13px]`や`py-[11px]`を、スケールの段に替える。

## 2. 色

- 無彩色のランプを1つ作り、方向の世界へ少し色味を寄せる。トークンのグラファイト、ウォーム、インクから選ぶ。同じやり方で自分のランプを作ってもよい。背景、浮いた面、境界、文字は、すべてそのランプから取る。
- アプリとダッシュボードでは、背景、面、境界、文字を無彩色のままにする。グラファイトか、同じくらい灰色のものにする。人は何時間も見る。色は内容が担う。背景がオレンジ、茶、青、緑に見えるなら、寄せすぎである。世界はアクセント、チャート、見せ場に出す。面には出さない。ランディングは、面を世界へもう少し寄せてよい。
- 文字の役割は3つにする。主、従、控えめである。少し違うラベンダーを10個作らない。
- クロムのアクセントは1色にし、まれに使う。主操作、選択、重要な数字のどれかを示す。
- 方向の見せ場は例外である。その中の色は豊かでよい。チャートの複数の色相、本物の素材を持つ描いた物体、自分の光を持つ画像である。世界の中に留める。各色には意味を持たせる。
- ブランドに本物の色があるなら、それをアクセントにし、面から外す。本物のブランド色が無いなら、アクセントは世界から取る。
- アクセントの上の文字は、コントラストを4.5対1以上にする。足りないなら、アクセントを暗くするか、暗い文字を乗せる。明るい面の上でアクセントを文字やインクに使うときも、同じコントラストにする。そこでは暗い階調を使う。
- 暗いテーマでは、主ボタンをランプのオフホワイトにし、文字を暗くしてよい。アクセントは、選択や重要な数字のような小さい場所に置ける。色付きボタンより、狙いがあるように見えることが多い。
- 意味の色は意味だけを運ぶ。良い変化は緑、エラーは赤にする。パレットに収まるよう、彩度を落とす。
- 面の上の色相グラデーション、グラデーション文字、色付きの発光、色付きの影、内容の背後の放射状の色のにじみと塊、ネオンの境界を消す。
- 境界は静かな極細の線にする。ランプの文字色を、不透明度6%から10%で使う。
- 暗いテーマの奥行きは、面の段と極細の線で作る。影では作らない。画像の上に浮く窓や物体は、柔らかい無彩色の影を残してよい。明るいテーマの影は、無彩色で、柔らかく、小さくする。
- グラデーションは、1つの無彩色の中の小さい階調だけ許す。アクティブな行が`#2b2b2b`から`#1f1f1f`へ変わるようなものである。色相から別の色相へは変えない。
- 画数の多い漢字は、小さいサイズほどコントラストを落とさない。控えめな文字が4.5対1を下回るなら、1段暗い色を使う。

## 3. アイコン

- アイコンやラベルの装飾に使った絵文字は、1つのセットの線アイコンに替える。プロジェクトにあるセットを使う。無いならlucideを使う。
- サイズと線幅は全体で1つにする。16pxか18px、線幅は1.5にする。
- アイコンの色は、文字の役割に合わせる。多くは従か控えめである。アイコンだけ別の色にしない。
- アイコンの箱の幅はすべての行で同じにする。ラベルまでの間隔は8か10に固定する。ラベルが揃う。
- 何も足さないアイコンは外す。カードの見出しごと、節のラベルごとの絵文字である。色が要る分類は、小さい状態の点にする。
- 全角の記号をアイコンにしない。`★`や`●`も、線アイコンか状態の点に替える。

## 4. 文言

このパスは、画面に出る形だけを見ます。文章の文体は扱いません。

- 見出しは短くする。1行か2行に収める。置き方はレイアウトのパスに従う。
- 感嘆符を付けない。半角と全角の両方を禁止する。`!`、`！`、`!!`は残さない。
- 挨拶の見出しにしない。`おかえりなさい`、`ようこそ`、`こんにちは`を題にしない。題はページ名か期間にする。例は`2026年10月`である。
- ラベルは短くする。`検索`にする。`何でも検索...`や`キーワードを入力してください`にしない。
- 変化の数字には、比べる相手を添える。`前月比+12%`や`前月より3件少ない`のようにする。
- 見出し、小見出し、ラベル、ボタン、一言のキャプションの末尾に句点を付けない。
- 英数字、`%`、`¥`は半角にする。全角の英数字にしない。`ＡＩ`、`１２３`、`％`を半角に替える。半角カナは使わない。
- ラベルでは、和文と数字の間を空けない。`前月比12%`のように続ける。全角スペースで位置を揃えない。
- 省略記号は`…`に揃える。`...`と`。。。`を混ぜない。プレースホルダの末尾には付けない。
- 日付は`2026年10月`か`2026/10/11`にする。`October 2026`や、月、日、年の順にしない。時刻は`14:30`にする。画面内で形式を1つにする。
- 円は整数にする。`¥48,210`か`4,821円`のどちらかに、画面内で揃える。円へ小数を付けない。ドルの画面でない限り`$`を使わない。
- 画面に出る数字は、ありそうなものにする。`123,456`や`[X]`にしない。
- 絵文字の付いたバッジは消す。`PRO`、きらめき付きの`New`、ロケット付きの`Beta`、`新着`、`ベータ`である。残すなら、絵文字の無い短い文字にする。

## 5. 文字

- 書体は、方向の性格から選ぶ。候補はトークンにある。本物のブランドの書体は残す。誰も選んでいないInterや、和文を持たない欧文フォントだけの指定は、システムのゴシックに替えてよい。画面の書体は1つにする。組み合わせる書体は、トークンの表のどの行からでも、多くて1つまで足す。数字とメタの等幅か、大きい見出しの明朝である。
- サイズはスケールから少数にする。太さは400と500にする。まれな強調だけ600までにする。700から900の見出しは使わない。グラデーション文字は使わない。
- 階層はサイズと色で作る。太さでは作らない。
- 欧文は文頭だけを大文字にする。`NAVIGATION`や`PAID THIS MONTH`のように、広い字間の大文字ラベルを、`Navigation`と`Paid this month`にする。和文のラベルは通常の字間で書く。`ナビゲーション`、`今月の支払い`である。全角の英字見出しにしない。
- 和文に斜体を使わない。`font-style: italic`は漢字を機械的に傾ける。強調は色か太さにする。傍点は文章向けなので、画面では使わない。欧文の強調にも斜体を使わない。
- 和文の`letter-spacing`は、どのサイズでも0にする。小さい文字を負の字間にしない。和文の字間を空けてラベルにもしない。かなと約物の全角の空きを詰めたいときは、`palt`を使う。`palt`は、かなの字幅をプロポーショナルにする。漢字のボディは、全角のまま残ることが多い。12pxのラベルで字が潰れるなら、そのラベルでは`palt`を外す。負の字間は、和文が混ざらない大きい欧文の見出しだけに使う。
- `font-synthesis: none`にする。太さと斜体の合成を禁止する。用意した太さだけを使う。
- 複数行の和文の`line-height`は1.7から1.8にする。1行のラベル、ナビ、ボタンは1.4から1.5にする。見出しは1.4から1.5にする。数字とロゴは1.2でよい。原文の1.02から1.08は、和文が混ざらない大きい欧文の見出しだけに残す。
- 和文は12px未満にしない。本文は14px以上にする。1行はおよそ25字から40字にする。40字を大きく超える本文は、幅を狭める。
- 数字は`tabular-nums`にし、画面内で形式を1つにする。1つが`¥48,210`なら、次を`¥124,860.40`にしない。ドルの画面なら`$48,210`のように、通貨と小数の有無を1つに決める。
- `line-break: strict`にする。小さい仮名や約物の前で、不自然に改行しない。

## 6. レイアウト

- 節とその順番は残す。節の中では、画面が明確になるなら、揃えとプロポーションを変えてよい。
- アプリとダッシュボードは、本物のアプリの比率を保つ。外枠はビューポートを満たす。サイドバーは240から280にする。内容は流動にし、幅の上限はおよそ1440から1600にする。ページの長さは内容に合わせ、最初の画面の下に節を続ける。アプリを、狭い中央の列へ縮めない。原文が背景の上の小さい窓なら、枠と背景を残して窓だと分かるようにする。中はデスクトップの比率を保つ。
- 最も強いランディングのヒーローは、風景である。生成した画像1枚が、端から端までヒーローを満たす。主題は片側に置く。見出しは、同じ画像の静かな空きに置く。製品プレビューは、下の端から立ち上がる。参照のヒーローを見る。
- 風景が無いなら、非対称の分割にする。文字は片側、ビジュアルは少なくとも幅の半分にする。または、大きい製品プレビューの上に文字を置く。すべてを縦に積んで中央に揃えるのは、テンプレートの初期値である。ビジュアルの無い短いヒーローだけ残す。
- 風景のヒーローでは、文字の塊を上部に置く。ナビと、製品プレビューの上端との間の、視覚的な中央である。幾何の中央より少し上にする。
- 分割では、文字の塊をビジュアルに対して垂直の中央へ置く。どちらの側にも、大きい空の角を残さない。ビジュアルがずっと高いなら、文字を下げずビジュアルを短くする。文字のそばに浮くカードや装置は、釣り合いが難しい。1つのまとまったビジュアルを優先する。ナビから見出しまでの余白トークンは、縦積みのヒーローで使う。分割のヒーローは中央へ揃える。
- 長い見出しは左へ揃える。中央揃えは、1行か2行の短い見出しだけにする。和文のヒーロー見出しは、1行およそ12字から20字で収める。
- 主操作は1つにする。従の操作は、その隣に多くて1つにする。それ以外はヒーローの外へ出す。
- ナビは静かにする。ロゴ、既存のリンク、ボタン1つである。ログインはその隣の静かな文字リンクにする。2つ目のボタンにしない。浮いたカプセル型のヘッダーを必須としない。狭い画面のリンクは、1つのメニューボタンに畳む。
- 最初の画面を1つの構図として組む。ヒーローはビューポートの高さを満たし、死んだ空の帯を残さない。内容が短いなら、中央に置く。または製品プレビューを低い位置から始め、下の端を越えて走らせる。ページがスクロールを誘う。
- 狭い画面では、読む順にすべてを積む。見出しはトークンのモバイルサイズまで下げる。ビジュアルは操作の後に置く。密なプレビューは、縮小せず、行と列を減らして単純にする。中の和文を12px未満にしない。

## 7. 細部

- 内側の角丸は、外側の角丸から、間のパディングを引いた値にする。4未満にはしない。コントロールは8から10、カードは12から16、パネルは14から20にする。すべてをカプセル型にしない。
- 件数とメタは、静かな文字にする。多くは等幅で、控えめな色にする。光るカプセルにしない。
- キーボードショートカットは、小さいキーキャップにする。
- チャートは控えめなグリッドと、控えめな等幅のラベルに乗せる。1つの系列の中で虹色の棒にしない。光る棒にしない。曜日を大文字の欧文にしない。チャートがプレースホルダの雑音なら、本物のことを伝えるデータに替える。
- チャートにも、文字と同じ階層を付ける。主チャートは1つにし、画面で明らかに最も大きくする。滑らかな線や、鏡写しの比較のように、丁寧に描く。他のデータは、種類を変えて小さくする。細い棒の順位リストや、短い表である。同じ大きさの2つ目のチャートにしない。
- チャートのアクセントは1つにする。今月、追っている線、伸びたプランのように、重要なものだけアクセントにする。他はランプの無彩色の段に置く。系列を区別しなければならないときだけ、複数の色相を使う。そのときも、1つがリードし、残りは静かにする。
- 統計カードは数字である。ラベル、大きい数値、比べる相手つきの変化を置く。埋めるためのスパークライン、集計、小さい棒、アイコンを足さない。装飾に見える。カードは、その数字が数えるものそのものなら、本物らしい物体を持ってよい。支払った売上のそばの領収書や、支出のそばの銀行カードである。そのダッシュボードで意味が立つ数だけ使う。それぞれが単独で読め、どれも小さいチャートではないようにする。
- 大きさを変える。同じ幅のカードを横に並べ、中身の種類も同じだと、テンプレートに見える。グリッドにリズムを付ける。3つか4つの密な統計を、広いチャート1つの上に並べる。または、広いチャートの隣に狭いリストを置く。
- チャートの種類はデータに合わせて選ぶ。推移は線、比較は棒、構成比は1本の積み上げ棒か棒つきリスト、1つの目標は進捗の棒にする。
- アクティブ状態は、面の小さい段と、極細の線のハイライトにする。発光つきのグラデーションにしない。
- ホバーとフォーカスは存在させ、パレットの中に留める。キーボード利用者には、見えるフォーカスリングを付ける。
- ロゴは、主な書体の製品名にする。印があるなら、単純な印を足す。グラデーションのワードマークと、きらめきのタイルは使わない。
- 方向の印は、属する場所にだけ出す。他では出さない。

## 8. ビジュアル

- 装飾の埋め草は消す。艶のある塊、球体、星雲、浮く立方体、光る格子、ホログラムの脳とロボットは、製品について何も言わない。
- ランディングのヒーローには、本当のことを見せるビジュアルを置く。
- ダッシュボードとアプリの画面は、生成画像をほぼ必要としない。見せ場は製品自身から来る。丁寧に描いたチャート、美しく置いた数字、製品写真やアバターのような本物の内容、生きて見える状態である。製品が扱う物理的なもの、たとえば金融アプリの支払いカードは、多くの場合コードで作った方がよい。本物の素材、柔らかいグラデーション、チップ、番号で作る。
- アプリの画像生成は、空の状態、導入、宣伝の見せ場か、ユーザーが頼んだときに限る。
- 画像生成のツールがあるなら、ランディングのヒーローの第一候補は、方向の世界の風景である。ヒーロー全体の背後に置ける横幅で生成する。文字が入る静かな空きを作る。色と気分はそれが担う。クロムはその上で静かに保つ。
- 風景の下に、またはツールが無いときのビジュアルとして、製品を見せる。ページがすでに約束しているもののプレビューを、コードで作る。プロジェクトのコンポーネントか、丁寧なHTMLと、ありそうなデータを使う。主画面、重要なカード1つ、製品が作る結果である。文言がすでに言っているものを見せるのは、機能の創作ではない。風景のヒーローでは、下の端から立ち上がり、端を越えて走る。
- 製品プレビューは、ただの無地のカードではなく、見せ場を持つ。中に描いた物体を置く。数字の上の支払いカード、豊かなチャート、世界の小さい物体である。これらは物体の種類なので、合うものを1つ使うのはよい。
- このパスの前に、[references/refs.md](references/refs.md)の参照を見る。構図、光、抑制、見せ場の置き方という質を取る。主題やレイアウトは取らない。
- 描いた物体と風景は、画像生成のツールがあるならそれで作る。無いなら、コードで作れるものを作り、残りはプロンプトを書き、正しい大きさの空の枠を残す。
- 主題の選び方、プロンプトのレシピ、画像の置き方は[references/visuals.md](references/visuals.md)にある。このパスの前に読む。

## 9. 動き

- 理由なく繰り返す動きを消す。生きていないものへの`animate-pulse`や`animate-ping`、見出しのシマー、呼吸する発光、浮く要素、パララックスである。
- `transition-all`、弾むスプリング、カードの`hover:scale`、ホバーで数pxを超えて動くものを消す。
- 何かを説明する動きは残す。ホバーは色か面の速い変化、押下はごく小さい縮小、メニューは開く位置から数px上がりながらフェード、変わった数字は補間する。
- 色、背景、境界、不透明度、変形をトランジションし、名前を付ける。Tailwindなら`transition-colors`や`transition-[transform,opacity]`にする。全部をまとめて指定しない。幅、高さ、top、left、マージン、大きいぼかしはアニメーションしない。弱い端末で引っかかる。
- イージングは画面で1本にする。長さはトークンから少数にする。反応は短く、入ってくるものは少し長くする。
- 読み込み時の登場は多くて1つにする。主な内容の、短いフェードと上昇に、小さい時間差を付ける。カードを別々の方向から飛ばさない。

## ストーリー動画

画面が段階的にAIっぽさを外していく、短い動画です。AIっぽさには赤い赤入れが付きます。作る前に[refs/story-dashboard-frames.webp](references/refs/story-dashboard-frames.webp)を見ます。順に並んだ8フレームです。あの動画は広く広まりました。仕組みは次のとおりです。

- **差し替えず、その場で変形する。** ページは1つである。各段階はCSSだけを変える。パディング、間隔、サイズ、色、角丸、影が、古い値から新しい値へその場で補間する。余白が開く。紫は抜ける。角は柔らかくなる。
- **波にする。** 要素は左上から順に、数十ミリ秒ずつ遅れて始める。全部が同時に切り替わらず、変化が画面を渡る。
- **文字を送る。** 変わる文言はぼけて消え、新しい言葉が1文字ずつ上がってくる。
- **先に赤入れする。** AIっぽさには、タグつきの赤い選択枠を付ける。余白の段階は赤い寸法を見せ、直ると白くなる。細部の段階は、角を半径つきで縁取る。
- **近く、短くする。** 正方形にし、最も変わる部分を近く切り取る。電話でも読めるようにする。長さはおよそ10秒にする。

動画の作成には数分かかります。ユーザーが欲しいときだけ作ります。

1. **ストーリーファイルは1つ。** `design-unslop-story/story.html`を作る。元の画面の独立した複製にし、スタイルはファイルの中に置く。元の規則はそのまま残す。それが段階0である。
2. **段階は3つから5つ。** パスをまとめ、各段階で見えるものが変わるようにする。`余白`、`色とアイコン`、`文字と文言`、`細部`のようにする。新しいチャートやビジュアルは最後の段階に入れる。headに`<meta name="unslop-steps" content="余白, 色とアイコン, 文字と文言, 細部">`と列挙する。名前に`余白`か`Spacing`があると寸法を出す。`細部`、`角丸`、`Details`、`radius`、`corner`のどれかがあると角の縁取りを出す。meta名の`unslop-steps`は、スクリプトが探す元の名前なので変えない。
3. **各段階は上に重ねるCSS。** 段階1の変更は`.s1`に、段階2は`.s2`に書く。`.s1 .card { padding: 24px }`や`.s2 body { background-color: #141415 }`のようにする。クラスは足される。段階3でも、段階1と2の規則は残る。値を変える。構造は変えない。ブラウザが補間できるようにする。
4. **補間できないものと、その扱い。** 補間できない変化は、次のように分ける。
   - グラデーション、発光、にじみは、専用の層に置き、その`opacity`を0へフェードする。下の無地の色は別に変える。グラデーション文字は`.from`のspanだけに置く。swapやその親には置かない。文字のクリップが、隠れている新しい文字まで捕まえる。
   - カプセルは、半径を高さの半分で書く。`23px`のようにする。`9999px`にしない。`9999px`にすると、角が最終フレームだけで変わる。
   - swapは控える。言葉が変わる場所だけにし、1本のストーリーで多くて8つにする。20個が一度にぼけると、2枚の絵のカットに見える。動画がそう見えてはいけない。太さ、サイズ、字間、色の変化は、それ自身が補間される。swapは要らない。新しい書体の家族は、その段階で直接切り替える。swapは使わない。
   - 文言そのものが変わるときは、次の形のswapにする。書体の家族だけが変わるときは、その段階で直接切り替え、swapは使わない。絵文字がアイコンになるときは、同じ箱で透明度を交差させ、swapに数えない。段階3で、古い文言がぼけて消え、新しい文言が送られる。

     ```html
     <span class="swap" data-at="3"><span class="from">おかえりなさい、田中さん！👋</span><span class="to">2026年10月</span></span>
     ```
   - アイコンになる絵文字は、同じ箱の中で絵文字の隣に新しいアイコンを置く。両方を絶対配置で重ね、その段階で`opacity`をクロスフェードする。これはswapではなく、上限に数えない。
   - 消えるもの、たとえばきらめき付きの`New`のバッジは、`data-out="2"`で段階2に畳む。
   - 現れるもの、たとえば凡例は、`data-in="4"`で段階4にフェードインする。場所は先に確保する。何も跳ねない。
5. **赤入れ。** 寸法は要素に生で付いていく。ものが動く間、数字は古い値から新しい値まで数える。人が見る瞬間なので、選び方を丁寧にする。
   - `data-gap`は、縦の積みの塊に付ける。サイドバーのブランド行、検索、ナビのグループ、プランのグループである。主カラムの見出し、統計の行、チャートでもよい。すべての行には付けない。画面が2pxの小さいタグで埋まる。積みごとに、測る間隔は4つから6つを目安にする。積みが複数なら、それぞれに名前を付ける。`data-gap="sidebar"`と`data-gap="main"`のようにする。
   - `data-radius`は、角が変わるボタンとカードの2つから4つに付ける。
   - `data-slop="グラデーション文字"`のように、AIっぽさを最初の短い拍のために印付ける。多くて5つにする。互いに離れた、最も分かりやすい例に、短いタグで付ける。任意である。参照の動画には無い。
6. **画面とその背景だけ。** 動画はストーリーのページを、そのまま見せる。余分な窓、境界、影を周りに付けない。ページ自身の背景が枠を満たし、画面だけが箱になる。画面がデスクトップの比率まで伸びる窓の中にあるなら、ストーリーでは左に固定する。横へ滑らず、右へ広がる。ストーリーのページは幅1440、高さ少なくとも900で描画される。寸法を`100vh`から取らない。`position: fixed`は背景の層だけに残す。
7. **カメラ。** 次のmetaが、ページのどの部分を枠いっぱいにするかを決める。値はページピクセルの横位置、縦位置、幅である。横位置と縦位置は、画面自身の左上に向ける。枠は周りのページ背景から始まり、最も見える変化の場所を近く切り取る。多くの場合、サイドバーか見出しと、最初のカードである。このmeta名も変えない。

   ```html
   <meta name="unslop-frame" content="0 0 960">
   ```
8. **描画する。** 次のコマンドを実行する。既定は正方形である。16対9には`--wide`を付ける。Playwrightとffmpegが要る。どちらかが無いなら、入れるコマンドを1つユーザーに伝える。先に生で見るなら、出力パスの代わりに`--play`で実行する。閉じるまで、ブラウザの窓で繰り返す。渡す前に、ffmpegで数フレームを抜き、それらを見る。ストーリーファイルと動画の確認は、1回の作業の描画上限に数えない。

   ```bash
   node <skill folder>/scripts/story.mjs design-unslop-story/story.html design-unslop-story.mp4
   ```
9. **ストーリーファイルは発表用である。** きれいな結果は、プロジェクト自身の技術で、普通のコードとして出す。`.s`クラスやストーリーの属性は付けない。

和文の文言は語の間に空白がありません。スクリプトは、和文の文字を1文字ずつ送り、連続する欧文は単語のまま折り返さないようにします。

## しないこと

- 製品名を変えない。名前にAIが入っていても変えない。本物のロゴはそのまま残す。ロゴ自体がAIっぽいとき、絵文字や、グラデーションのタイルの中のきらめきなら、平らに描き直す。新しい書体のワードマークだけか、製品の考えから来た単純な字形を、1つの無彩色で描く。艶のある球、グラデーションの球、発光、グラデーションのタイルは禁止する。一目でAIに見える。
- 製品が何であるかを変えない。機能、内容、節の順番は、ユーザーが追加を頼むまで残す。何も意味しないプレースホルダの内容は、意味のある内容に替えてよい。
- 消した装飾の代わりに、新しい装飾を置かない。ガラス、グレイン、ノイズ、ネオン、弁当グリッドのように、1つの流行を別の流行へ取り替えない。
- 機能、主張、データを作らない。
- すべての製品を同じ見た目に戻さない。方向が、パレットの色味、書体、ビジュアルを決める。癖で決めない。
