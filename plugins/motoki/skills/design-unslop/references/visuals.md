# ビジュアル

装飾の埋め草を、この製品に属するビジュアルへ替える方法です。画像のツールがあるときは、生成の仕方も書きます。

## 何を見せるかを決める

1. **画面に必要か。** ダッシュボード、設定、ほとんどのアプリ画面には要らない。ランディングのヒーローと、空の状態には、多くの場合要る。
2. **画像のツールがあるか。** ランディングのヒーローでは、世界の風景をヒーロー全体の背景として生成する。主題は片側に、見出しの静かな空きは反対側に置く。製品は下の端から立ち上がらせる。これが最も強いヒーローである。
3. **製品を見せる。** 風景の下に、またはツールが無いときのビジュアルとして、ページがすでに約束しているもののプレビューをコードで作る。見出しを証明する1つの瞬間を選ぶ。アプリ全体は見せない。予定のツールは、予約の入った1週間を見せる。コードレビューのツールは、コメントつきの差分を1つ見せる。習慣のアプリは、1枚のカードの連続記録を見せる。プロジェクト自身のコンポーネントがあるなら、それを使う。無いなら、新しいパレットの丁寧なHTMLを使う。ありそうなデータと、本物らしい名前にする。窓や装置の枠は、その方が分かるときだけ使う。
4. **風景を1文で書く。** 方向の世界と性格を使い、生成の前に主題を平易な1文で書く。1文で言えないなら、まだ明確ではない。

次の例は、良い文の形を示すだけです。再利用しません。目の前の製品から導きます。

- バックアップを守るツール → 暗い岩の海岸の小さい灯台。光が霧の中へ伸びている
- 瞑想のアプリ → 夜明けの窓辺で湯気を立てる、茶の一杯
- 物流のAPI → 穏やかな灰色の海を、真上から見たコンテナ船が1隻
- 言語学習のアプリ → 午後の日が差すカフェの机の上の、手書きの単語カードの束

製品が文字どおりそれらについてでない限り、AIの初期値を避けます。艶のある塊、球体、星雲、液体のクローム、浮く立方体、ネオンの回路、ホログラム、光る脳、ロボット、ロケット、結晶の形は使いません。

近年の日本のアニメ映画のような背景は、下の様式の1つです。暖かい、希望のある、人に近い製品にだけ使います。和文のUIだからという理由では選びません。

## うまくいく様式

性格に合うものを1つ選び、ページ全体でそれを保ちます。

- **描いた背景。** 主題が1つの、穏やかな空か風景である。近年の日本のアニメ映画の背景のように描く。輪郭のある雲と柔らかい光にし、文字のための開いた空を残す。暖かい、希望のある、人の近くの製品へ向く。
- **1つの物体の映画的な写真。** 無地の場に、単純で劇的な光を当てた本物のものを1つ置く。霧の中の灯台や、空中の紙の物体のようにする。落ち着いた、真面目な、信頼できる製品に向く。
- **柔らかい様式化の3D。** マットな素材と穏やかな光の、小さい風景か物体を1つ置く。草原に立つ戸口のようにする。遊びのある、親しみやすい製品に向く。
- **製品の物体のレンダリング。** 製品から来た本物らしい物体を置く。支払いカード、電話、小包のようにする。本物の素材で、スタジオの光を当て、画面の中の見せ場に使う。物理世界の製品に向く。
- **光と光学。** 暗い場の上の、物理現象を1つ置く。プリズムで分かれる光のようにする。技術やデータの製品に向く。
- **版画。** 柔らかい色味の紙の上に、1つのインクで描いた単色の版画か木版である。書体とパレットも同じ世界に属させる。来歴、手仕事、編集の声を持つ製品に向く。
- **画像の上のコードの扱い。** 生成した画像を、ページのパレットの字形、点、2色に描く。ページに合わせて作る。[effects.md](effects.md)を見る。

失敗しやすいものは、次のとおりです。

- フィルムグレイン、紙のグレイン、まだらの質感を頼むプロンプト。モデルは画像へ細かい市松を焼き込む。質感が要るなら、コードで足す。
- 版画、木版、リソグラフのような印刷の様式を画像1枚だけに使い、ページの残りが無地の現代的な画面である場合。フィルタに見える。ブランド全体がその様式の中にあり、書体と紙のパレットが合うなら、うまくいく。柔らかい色味の紙の上の、単色の版画のようにする。
- 主題が複数、または忙しいコラージュ。考えが1秒で読めなくなる。
- どの種類でも、紫と青の艶のある抽象。

## 見せ場の物体

風景全体のほかに、画面へ置く単体の物体を生成します。支払いカード、電話、小包、コーヒーカップ、製品の世界のノートのようにします。コードのプレビューが本物らしくなります。

- 物体は1つにする。スタジオの光を当て、ページの色そのものの無地の背景に置く。柔らかい接地面の影を付け、枠の中に他を置かない。
- レイアウトに要る角度を指定する。`20度傾け、少し上から見る`のようにする。
- ツールが背景を消せるなら、物体を切り抜く。できないなら、マスクでページの色へ溶かす。
- カードか窓の端に重ね、少し回転して置く。影はランプの最も暗い色で柔らかくする。UIと同じ空間に座る。
- 背景除去は、背景色に近い暗い部分を消す。電源の切れた黒いディスプレイが抜ける。端末の表示面は、対照的な無地の色で頼む。または、切り抜きの外縁からアルファを作り直す。
- 生成した装置の上に本物のUIを見せるなら、パース無しの正面で生成する。表示面の矩形を測り、その上にHTMLを置き、両方を一緒に回転する。文字は鋭く、本物のまま残る。
- 1つのビジュアルの中のすべては、同じ話をする。一覧が顧客への請求`INV-0142`を見せるなら、電話も同じ顧客、番号、金額を見せる。

## 生成する

持っているツールの中から、画像生成を探します。fal、Replicate、OpenAI images、HiggsfieldのMCPサーバや、デザインツールです。あるなら、次のようにします。

- 実行前に、プロンプト、モデル、サイズをユーザーへ見せて聞く。有料の生成になることがある。
- 1回だけ実行する。もう一度試す前に、1文とパレットに照らして結果を判断する。同じプロンプトを引き直さず、プロンプトを変える。
- 結果はプロジェクトのアセットへ保存する。一時的なURLにはしない。

ツールが無く、画面に風景か物体が要るなら、ビジュアルのパスの前にそう言います。fal、Replicate、OpenAI images、HiggsfieldのMCPサーバのように、1つをつなぐことを提案します。つながってから続けます。ユーザーが省くなら、枠は空けたままにし、プロンプトは報告に書きます。ページには書きません。空の枠は、その大きさそのものの平らな面の段にします。レイアウトの半径を付け、中に文字を置きません。未完成のものが誤って出荷されないようにします。どの種類のサービスが生成できるかと、保存するファイル名をユーザーに伝えます。

## プロンプトのレシピ

プロンプトは、次の部分をこの順で組み立てます。

- **主題。** 具体的で、物理的な1文にする。
- **場。** どこにあるかを、単純に保つ。
- **光とパレット。** ページに合わせる。端が溶け込めるよう、ページの背景色を名指しする。光の方向も書く。
- **様式。** 性格に合う、明確な方向を1つにする。映画的な写真、柔らかい3Dレンダリング、編集的なイラスト、リソグラフ、描いた背景のようにする。流行ではなく、製品に合うものを選ぶ。
- **構図。** 文字の場所が残るように、主題の位置を書く。`主題は右半分、左は静かな空き`のようにする。ヒーロー全体の背後の風景は、16対9かそれより広く頼む。下の5分の1も静かにする。製品プレビューがその上に立ち上がる。端は、コードでページの色へフェードする。
- **除外。** 文字、字母、ロゴ、UI、透かしを入れない。
- **形式。** 枠の縦横比で、表示サイズの2倍にする。

## ページに置く

- WebPかAVIFで、表示サイズの2倍として書き出す。何が写っているかを言う、本物の`alt`を付ける。
- 画像の端をページの背景に合わせる。合わないなら、マスクでフェードする。`mask-image: radial-gradient(closest-side, #000 70%, transparent)`のようにする。または、ページの色のグラデーションを重ねる。違う色のページの上の硬い矩形は、AIっぽさの兆候である。
- 静止のままか、主題に合う遅くてかすかな動きを1つ付ける。パララックスは付けない。
- ページのパレットへの2色化のような、コードの扱いは、生成画像をその場のものに感じさせる。性格に合うときだけ使う。新しい装飾としては使わない。
- ヒーロー画像は高い優先度で読み、寸法を固定する。レイアウトが跳ねない。
