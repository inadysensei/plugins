# 検出結果を分ける

FAILEDの検出結果1件を、是正、抑制、証拠不足、対象外のどれか1つにします。
単位は検出結果の`Id`です。コントロールIDが同じでも、検出結果ごとに分けます。件数やアカウントではまとめません。

## 手順

一度のトリアージで確認する検出結果は10件とします。ユーザーが指定した場合はその件数です。
この件数は検出結果の件数です。コントロールの件数ではありません。
指摘の修正作業はまだ実施しません。

1. `Compliance.Status`を見る。`FAILED`でなければ対象外である。`NOT_AVAILABLE`も対象外である。
2. `Workflow.Status`が`SUPPRESSED`なら、既存の状態を書いて対象外にする。
3. `Remediation.Recommendation.Url`を見る。空なら`aws securityhub batch-get-security-controls`でそのコントロールIDを読む。応答の是正URLを使う。URLがまだ無ければ証拠不足。
4. 是正URLを開く。
5. リソースIDを、IaCリポジトリから検索する。コントロールIDかリソースIDを含む記述も検索する。
6. 判定を1つに決める。

## 推奨アクションの判定

指摘を是正するか抑制するかを判定します。

### 是正するべきもの

- `Severity.Label`が`CRITICAL`、`HIGH`のもの
- 簡単に修正でき、本番環境への影響が発生しないもの

### 抑制するべきもの

- 指摘されているリスクが実際にはほぼ発生しないと考えられるもの
- リスクに対してコストベネフィットが著しく低いもの

## 出力

見出しは検出結果IDにします。タイトルが同じでも、検出結果ごとに見出しを分けます。

```markdown
# トリアージ結果

## 【深刻度】 検出結果タイトル(検出結果ID)

### リソース

 - リソース名: <リソース名>
 - リソースARN: <リソースARN>

### 指摘事項

Security Hubの指摘事項と推奨アクションを日本語で書く

### 判定

抑制/是正/証拠不足/対象外

### 根拠

根拠を数文で書く

```
